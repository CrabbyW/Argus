---------------------------------------------------------------------
MIGRACE - PROČ SE MUSELA PŘEPSAT RUČNĚ
---------------------------------------------------------------------

EF u scaffoldu sám hlásí "may result in the loss of data" a vygeneruje
pořadí, které by data ZAHODILO:

  řádky 25-37   DropColumn RootPath, PhysicalPath, Tags, ApplicationId
  řádek 54+     CreateTable RootPaths, PhysicalPaths, Tags, ...

Tedy zahodí sloupce dřív, než vůbec vytvoří tabulky, které mají ty
hodnoty převzít. Back-fill nevygeneruje vůbec žádný.

Ruční pořadí v Up() je proto:

  0. Zálohy __InstallationsBackup_Phase2 a __AppRepositoriesBackup_Phase2
     (SELECT ... INTO) - kvůli ověření po migraci i kvůli rollbacku
  1. GUARD: THROW 50002, pokud existuje štítek delší než 64 znaků
     (dřív se vešel do sloupce 512, nový sloupec je 64 -> tiché uříznutí)
  2. CreateTable RootPaths, PhysicalPaths, Tags
  3. Back-fill INSERT ... SELECT DISTINCT s LTRIM(RTRIM(...))
     - trim je nosný: cíl má unikátní index, '/app' a '/app ' by byly
       dva zdroje na jedno místo
     - prázdný RootPath -> '/' (tak to měl starý sloupec v defaultu)
     - štítky přes CROSS APPLY STRING_SPLIT(i.Tags, ';')
  4. AddColumn RootPathId a PhysicalPathId jako NULLABLE
  5. UPDATE ... FROM ... JOIN na oříznutý text -> naplnit oba FK
  6. GUARD: THROW 50001 / 50004, pokud po back-fillu zbyl NULL
  7. AlterColumn RootPathId -> NOT NULL
  8. CreateTable InstallationTags + INSERT DISTINCT
     - DISTINCT je nosný: uložené "web;web" by porušilo složený PK
  9. CreateTable InstallationRepositories, pak:
     - vazby se zakládají rovnou na KANONICKÝ řádek
       (MIN(Id) per RepositoryUrl), teprve pak se duplicity mažou,
       takže žádná vazba nikdy neukazuje na řádek, který má zmizet
     - join vidí i měkce smazané instalace ZÁMĚRNĚ: vyřazená instalace
       si nechá historii, odkud se brala
     - repozitář aplikace bez instalací si řádek nechá, jen zůstane
       bez vazeb -> nic se nemaže, není na čem abortovat
     - DropColumn ApplicationId
 10. DropIndex UX_Installations_Deployment (obsahuje RootPath!),
     teprve pak DropColumn tří stringů
 11. Nové indexy a FK; UX_Installations_Deployment znovu nad RootPathId
     se STEJNÝM jménem i filtrem [IsEnabled] = 1

Down() je zrcadlo: sloupce zpět, naplnit z číselníků, štítky složit
přes STRING_AGG(t.TagName, ';') WITHIN GROUP (ORDER BY t.TagName),
teprve pak zahodit nové tabulky.
U repozitářů je Down ZTRÁTOVÝ a je to v souboru napsané: repozitář
sloužící instalacím více aplikací se vrací pod MIN(ApplicationId).

POŽADAVKY: STRING_SPLIT potřebuje compatibility level >= 130
(SQL Server 2016), STRING_AGG v Down() SQL Server 2017+. Ověřit:
  SELECT compatibility_level FROM sys.databases WHERE name = DB_NAME();
